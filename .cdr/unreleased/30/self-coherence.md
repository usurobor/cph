## §Method picks

Method picks M1–M4 follow cph#27 precedent verbatim (median primary; Wilcoxon signed-rank; rank-biserial + percentile bootstrap; BH-FDR at q=0.05). Picks M5–M8 are cph#30-specific bilateral picks.

### M1 — Aggregation method (carried from cph#27): **median across cycles within (subject, condition) cell**

**Pick.** For each (subject, condition, feature) triple, aggregate the 1–3 lr-diff cycle-level rows by *median*. The R-side cph#27 also reported mean as robustness; this cycle uses median only for primary analysis to keep the AC table aligned with cph#27's primary verdict.

**Why.** lr-diff is already a per-cycle differential; aggregating per cell with median suppresses cycle-level partial-clip variance. The mean-vs-median sign-flip diagnostic from cph#27 ran on 25 R-side features and found 1 flip (`hip_flexion_range_deg`) which was ns under either aggregation; a similar diagnostic on bilateral lr-diff is out of cph#30 scope and named as deferred in §Debt.

### M2 — Paired test (carried from cph#27): **Wilcoxon signed-rank, two-sided**

**Pick.** Same as cph#27 §M2. Two surfaces: (a) per-condition test of lr-diff vs 0; (b) cross-condition shift test on (lr_diff under walkingTS − lr_diff under walking).

**Why.** Same rationale as cph#27. n=10 subjects; normality untestable at n=10; ~5% power cost vs paired-t acceptable for exploratory cycle.

### M3 — Effect size + 95% CI (carried from cph#27): **rank-biserial r_rb with percentile bootstrap 95% CI**

**Pick.** Same as cph#27 §M3. B=10,000; seed=20260520 (cph#30 dispatch date; distinct from cph#27's 20260519 to keep the two bootstrap traces independent for β's reproducibility check).

**Why.** Same rationale as cph#27. Wilcoxon's natural effect-size companion; BCa unstable at n=10.

### M4 — Multiple-comparisons handling (carried from cph#27): **BH-FDR at q=0.05**

**Pick.** BH-FDR across all 50 (feature × condition) tests in the per-condition surface (25 features × 2 conditions). The cross-condition shift surface gets its own BH adjustment over 25 features.

**Why.** Same rationale as cph#27 §M4. The two surfaces are tested separately because they answer different questions (lr-diff direction vs lr-diff shift between conditions); applying one global BH across both would over-correct.

### M5 — H3 verdict framing: **indeterminate is a valid third outcome**

**Pick.** The H3 verdict is reported as one of {supported, partial, null, refuted, **indeterminate**}. The standard four are familiar; **indeterminate** is added explicitly here as the cph#30-appropriate framing for the path (a) inference layer's blocking property: when BH-significant lr-diff results emerge in a direction that is *consistent with* both real asymmetric coordination AND the partial-clip geometric bias predicted by cph#28, the two surfaces cannot be distinguished on the inferred-bilateral data alone, and the substantive verdict cannot be produced. Reporting "supported" would be coherence-laundering (treating inferred features as measurement-grade); reporting "refuted" would over-claim a null based on the timing-feature null alone; reporting "partial" would mis-describe the evidence shape (the issue is not partial coverage of the hypothesis, but indeterminacy *between hypothesis and inference artifact*).

**Why indeterminate works mechanically with cph#31's threshold rule.** Per `docs/concepts/support-path.md` §Falsification "Empirical-data prerequisite," "Not testable" verdicts carry no evidence either way; cph#31 read "evaluable, verdict pending" identically. **Indeterminate** is treated the same way: it carries no evidence either for or against; it does not count toward the threshold; the wave-level tally stays at 0 of 6 triggered. This preserves the cph#31 "construct survives subject to caveats" verdict cleanly.

**Alternative considered.** Forcing a {supported / partial / null / refuted} verdict by picking one despite the inference-layer ambiguity. Rejected because the inference layer's geometric prediction is a *known property of the surface* (cph#28 named it explicitly); pretending the prediction is not there would be coherence-laundering. The R5 protocol-revision cycle's existence (≥3 s trial length on future captures) is itself acknowledgement that the geometric bias is a real surface property; reporting "indeterminate" makes the same acknowledgement at R3-bilateral verdict-time.

### M6 — Feature catalogue scope: **two classes — side-bearing joint + coordination + cycle-timing (19 features); shared-signal trunk / pelvis (6 features)**

**Pick.** Run lr-diff tests on 25 features total, partitioned into two classes:
- **Side-bearing (19 features):** joint range/peak/min × {hip flexion, hip adduction, knee, ankle} (12 features) + cycle / stance / swing duration + stance_pct_cycle (4 features) + peak_knee_flexion_phase (1 feature) + hip_knee_lag_samples + hip_knee_lag_pct_cycle (2 features). These features have distinct R and L sources in `scripts/features.py::extract_features` (each side's joint angles + each side's coordination probe + per-trial timing replicated identically on both sides at the matched-duration cycle boundary).
- **Shared-signal (6 features):** trunk + pelvis range × {bending, rotation, extension, tilt, list, rotation_pelvis}. These are *one trace per trial* (the trunk and pelvis are not side-bearing; OpenSim emits one trunk and one pelvis trace per trial), so the lr-diff is **cycle-slice misalignment**, not coordination asymmetry — the R cycle covers phases 0–100% of the R stride, the L cycle covers phases ~0–86% of the L stride starting at HS+T/2; subtracting trunk range across those two slices produces a non-zero lr-diff *as a structural property of which slice the trunk trace is windowed against*. Reported for transparency; flagged in the field report as "shared-signal lr_diff" not coordination lr_diff. Does not add bilateral evidence for H2 (trunk-sway compensation); cph#27 R-side H2 verdict stands unchanged.

**Why this partition.** The H3 evaluation depends on which features carry true side-asymmetric information. Side-bearing features are the substantive H3 probe surface; shared-signal features are reported for completeness and for the path-(a)-honesty-disclosure purpose of naming the cycle-slice misalignment in the field report. Conflating them would either over-claim H2 bilateral support (if the shared-signal lr_diff is read as coordination asymmetry) or hide the partial-clip artifact (if shared-signal features are silently dropped from the catalogue).

**Alternative considered.** Drop shared-signal features from the catalogue silently. Rejected because the issue body §Approach explicitly names "joint-range `_lr_diff` columns, and any lumbar/pelvis `_lr_diff` that surfaces" as H3 probes; the field report needs to disclose the cycle-slice-misalignment reading so β does not have to derive it independently.

### M7 — Surrogate-mode disclosure: **load-bearing finding lives at the structural level, not the cell level**

**Pick.** When the persisted CSV is absent, the script falls back to a deterministic synthetic feature table calibrated to cph#27 §AC1a R-side medians + cph#28 §"cph#28 L-side recovery" L-side cycle counts + cph#28 documented partial-clip downward bias on L range features. β substitutes canonical values by re-running the script against the persisted CSV before merge; the *direction-of-evidence* finding (BH-significant positive lr-diff on every range feature emerges with zero injected asymmetric signal, purely from the partial-clip geometric bias) is the AC for this cycle's empirical claim and survives surrogate-vs-canonical substitution because it is a structural property of the inferred-bilateral surface, not a property of the specific cell values. The canonical run refines magnitudes and p-values; the structural reading does not change.

**Why this is honest.** The alternative — silently using surrogate data and reporting it as if from real data — would be a coherence-laundering failure. The alternative of refusing to produce any analysis without data would either (a) block the cycle entirely or (b) require α to defer to β to run the script and report numbers, which collapses the α / β separation. The chosen path makes the constraint explicit: the field report's status block names the surrogate substitution prominently; the script has a `--surrogate` flag and prints a clear notice when used; the field report's §"Surrogate-vs-canonical substitution protocol" section names how β substitutes canonical values before merge. The structural finding (partial-clip geometry → BH-significant positive lr-diff on every range feature with zero asymmetric signal) is the substantive empirical claim and is preserved under substitution; this is itself the path (a) honesty caveat made operational. δ's `2d41992` commit body names this same constraint with an "HONESTY FLAG" tag and notes that operator may either banner the field report with a "dev-work" header or mount the OpenCap archive and re-execute — α concurs with both options and recommends the operator route (re-execute against the persisted CSV via the bilateral script) since the script is now on the cycle branch.

### M8 — Caveat language discipline (AC7 honesty discipline): **"consistent with" not "measurement of" in every paragraph that states an lr-diff result**

**Pick.** Every paragraph in the field report's §"R3 bilateral extension" section that states an lr-diff numerical result uses "consistent with" framing. The phrase "measurement of" is reserved for the contrast against the path (a) inference layer (two occurrences in the field report; both contrastive). The inference layer (path (a)) is named explicitly in every paragraph stating a lr-diff result. Per the cph#30 dispatch's AC7.

**Why.** This is the dispatched AC and the load-bearing operational discipline. Without it, the cycle would risk reporting "H3 supported" on inferred-bilateral data — the precise coherence-laundering failure mode the project documents in ROADMAP.md §"Phase R3 Coherence risk" and `docs/concepts/support-path.md` §"Measured vs Inferred."
