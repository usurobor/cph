# Roadmap

This file tracks the gates by which the Coherence Path Hypothesis is validated, revised, or abandoned.

The hypothesis itself lives in [docs/concepts/coherence-path-hypothesis.md](docs/concepts/coherence-path-hypothesis.md). Live operational status lives in [PROJECT.md](PROJECT.md). The project changelog lives in [CHANGELOG.md](CHANGELOG.md). This roadmap names what each phase must achieve and where each phase stands.

## Goal

Validate, revise, or abandon the Coherence Path Hypothesis through gates that name what each phase must produce, what currently exists, and what blocks the next transition.

## How to read this file

Each phase carries seven fields:

- **Goal** — what the phase must achieve.
- **Current evidence** — what merged artifacts show today; cited from owning files.
- **Gate** — the condition that closes the phase. "Closes" means status transitions out of ACTIVE / REVISE into GO.
- **Status** — one of NOT STARTED, ACTIVE, GO, REVISE, STOP. R5 and R6 carry their own status phrasings per the master issue.
- **Coherence risk** — how running this phase could damage project coherence (terminology drift, evidence/claim drift, identity drift). Not an empirical risk; the empirical risks live in the protocol and field-report files.
- **Next action** — the next concrete step the phase requires.
- **Owning files** — the surfaces that this phase reads from and writes to.

Phase transitions are gate-based. Each phase moves only when its specific gate is satisfied.

## Phase R2 — Contact-event and segmentation reliability

- **Goal:** Establish reliable heel-strike detection and gait-cycle segmentation on real Mocap calcaneus markers, on both sides or with a clearly justified one-side analysis path.
- **Current evidence:** Per [`reports/field-report-01-existing-data-zeroth-pilot.md`](reports/field-report-01-existing-data-zeroth-pilot.md) §Segmentation Status (post-fix), `scripts.segmentation.detect_heel_strikes` now uses robust-percentile normalization plus stance-region depth/length gating: each contiguous run of `yn < 0.30` (where `yn = (smoothed_heel − q05) / (q95 − q05)`) lasting ≥150 ms AND reaching `< 0.10` is one stance phase, with HS at the first sample inside that deep-stance plateau. The detector is invariant to absolute height, baseline offset, and amplitude. Result: 60/60 R-side trials produce ≥1 cycle (100%; 30/30 natural + 30/30 trunk-sway); L-side fires HS on all 60 trials but only 1 trial yields a complete L cycle, with 47/60 ending in mid-swing and 12/60 starting in mid-swing — a property of the source archive's trial cropping (~1.3–1.5 s, R-stride-aligned). The smoke synthetic regenerates 7+7 = 14 cycles at the expected 1.1 s stride period. The bounded revision shipped on [`cycle/port-segmentation-fix`](https://github.com/usurobor/cph/tree/cycle/port-segmentation-fix) (cph#26 step A); the original orthogonal branch `origin/cycle/segmentation-real-data-fix` (tip `a95415c`) was its precursor and is superseded.
- **Gate:** Detector fires on ≥60% of real Mocap walking trials per side, *or* the report explicitly justifies a one-side analysis path with documented reasoning for the asymmetry.
- **Status:** GO. The detector clears the 60% threshold cleanly on the R-side, and the one-side analysis path is justified in [`reports/field-report-01-existing-data-zeroth-pilot.md`](reports/field-report-01-existing-data-zeroth-pilot.md) by per-(trial, side) classification (`scripts/segmentation_diagnostics.py`) showing the L-side mid-swing endings are a trial-cropping property of the source archive, not a detector failure. L-side cycle recovery (contralateral-anchored detection or wider-window IK) is a downstream R3 / friend-pre-pilot-capture concern, not an R2 detector concern.
- **Coherence risk:** Reading R2 GO as removing the R1 REVISE constraint. R2 closes the detector subproblem; R1 stays REVISE because the bilateral construct still depends on L-cycle yield, which is a data-shape constraint that R2 cannot address. A second risk: treating smoke-test passing as construct evidence; the smoke generator hardcodes the heel shape the detector targets, which is a tautology, not validation.
- **Next action:** Closed. Future work on L-cycle recovery is named in R1's Next action and in [`reports/field-report-01-existing-data-zeroth-pilot.md`](reports/field-report-01-existing-data-zeroth-pilot.md) §Decision.
- **Owning files:** `scripts/segmentation.py`, `scripts/segmentation_diagnostics.py`, [`notebooks/existing-data-processing.ipynb`](notebooks/existing-data-processing.ipynb), [`reports/field-report-01-existing-data-zeroth-pilot.md`](reports/field-report-01-existing-data-zeroth-pilot.md).

## Phase R3 — First construct-level evidence

- **Goal:** Test whether the per-cycle features named in [`analysis/features.md`](analysis/features.md) show stable, interpretable coordination signatures at the subject level under condition response (natural vs trunk-sway), without pseudoreplication.
- **Current evidence:** Per [`reports/field-report-03-construct-evaluation.md`](reports/field-report-03-construct-evaluation.md) (2026-05-19 cph#27 R3 first-pass), the R-side aggregate analysis (10 subjects × 2 conditions × 25 numeric features, paired Wilcoxon signed-rank on per-subject medians, BH-FDR at q=0.05) produced 7 BH-significant condition responses including a textbook-magnitude lumbar bending increase (+18.3°, r_rb = +1.0, all 10 subjects in agreement) and a distal sagittal contraction (ankle range −6.6°, r_rb = −1.0). Hypothesis 1 (sagittal-dominant load transfer) survives in a *distal-contraction-under-proximal-compensation* form; the hip-as-sagittal-driver sub-claim does not survive on R-side. Hypothesis 2 (trunk-sway compensation) survives in a *trunk-segment-driven* form; the hip-adduction-as-compensation sub-claim does not survive on R-side. Hypothesis 3 (asymmetric phase-coupling) remains structurally non-testable — n=1 L-cycle in the archive, no R/L pairs at matching (subject, cycle_number) for any subject. Three candidate support-path hypotheses surfaced with mechanism and condition-bound scope: Lateral-trunk substitution path, Distal sagittal contraction under proximal compensation, Cadence-slowdown signature. Reproducible via [`analysis/r3_subject_aggregate_tests.py`](analysis/r3_subject_aggregate_tests.py).
- **Gate:** Subject-level (not cycle-level) condition-response analysis demonstrates stable feature distributions per subject per condition; aggregation method excludes pseudoreplication; at least two of the three framed hypotheses survive specification under adequate n.
- **Status:** **Partial GO on R-side.** The R-side aggregate analysis satisfies the gate's three sub-conditions on R-side surfaces: aggregation is per-subject (pseudoreplication avoided); feature distributions are stable across subjects within each condition (r_rb = ±1.0 on four BH-significant features); two of three framed hypotheses (H1, H2) survive specification in their R-side-evaluable forms. Bilateral completion of the R3 gate awaits cph#28's L-cycle recovery.
- **Coherence risk:** Pseudoreplication — reporting per-cycle distributions as if cycles were independent observations. Adjacent risks: `support path` and `coherence path` losing their distinction once recurrence/distinguishability tests run; alternative explanations (trial crop, marker artifact, camera setup, subject morphology, condition labels alone) being collapsed into the "construct survives" verdict instead of being named separately. A new risk surfaced by cph#27's partial GO: reading R-side partial-GO as bilateral-construct evidence. The field report explicitly frames partial GO as R-side only and notes that R1's transition is owned by cph#28, not by R3.
- **Next action:** After cph#28 produces L-side cycle yield sufficient for R/L pairing, re-run the aggregate analysis with bilateral coverage and append a Fix-round / R3-bilateral section to `field-report-03` (or open a new R3-bilateral cycle) that evaluates H3 substantively and completes the R3 gate.
- **Owning files:** [`analysis/features.md`](analysis/features.md), [`analysis/feature-table-schema.md`](analysis/feature-table-schema.md), [`analysis/feature-summary-zeroth-pilot.md`](analysis/feature-summary-zeroth-pilot.md), [`analysis/left-right-comparison.md`](analysis/left-right-comparison.md), [`analysis/r3_subject_aggregate_tests.py`](analysis/r3_subject_aggregate_tests.py), [`notebooks/existing-data-processing.ipynb`](notebooks/existing-data-processing.ipynb), [`reports/field-report-03-construct-evaluation.md`](reports/field-report-03-construct-evaluation.md).

## Phase R4 — Support/coherence-path inference

- **Goal:** Determine whether the coordination signatures from R3 justify the inference to a support/coherence path, distinct from measured data alone.
- **Current evidence:** Per [`reports/field-report-03-construct-evaluation.md`](reports/field-report-03-construct-evaluation.md) §"Falsification re-evaluation on R-side" (cph#27 R3), 0 of 6 falsification conditions are triggered; 5 of 6 are cleanly NOT triggered on R-side surfaces (conditions 1, 2, 4, 5, 6 — including new R-side substantive verdicts for conditions 1, 2, and 6 from the aggregate analysis); 1 (condition 3, L/R asymmetry) remains not testable on this archive (L=1 cycle; cph#28 owns the gate). The mechanical "below the 4-condition NO-GO threshold" reading is *not* construct-survival evidence; it reflects R-side-only evaluability. The hypothesis is neither validated nor refuted. R-side surfaces clear the falsification conditions they are *capable of triggering*; the bilateral surface (condition 3) is unresolved.
- **Gate:** The falsification table from [`docs/concepts/support-path.md`](docs/concepts/support-path.md) §Falsification is evaluated on data capable of triggering each condition; the evaluation distinguishes measured surfaces (kinematics, timing, segment coupling, asymmetry, condition response) from inferred interpretation (coherence-path organization, load-transfer reading); alternative explanations are named per [`docs/concepts/failure-conditions.md`](docs/concepts/failure-conditions.md).
- **Status:** **Partially evaluable on R-side** (5 of 6 conditions readable, 0 triggered). Full evaluation awaits cph#28's L-cycle recovery — condition 3 transitions from "not testable" to a substantive verdict only after R/L pairing becomes possible.
- **Coherence risk:** Treating coherence-path inference as a measurement. The terminology distinction (Coherence Path Hypothesis = the claim; support path = the operationalized pattern) collapses if a phase-4 write-up calls a measured feature a "coherence path" without inference, or treats the seven gait families as proven by a clustering output rather than as candidate surface expressions. *Coherence laundering* — treating a clean feature table or a self-consistent repo as substantive evidence for the hypothesis — is the failure mode to avoid. A second risk surfaced by cph#27: reading the R-side "0 of 6 triggered" as bilateral-construct survival evidence. The field report explicitly frames the verdict as R-side only.
- **Next action:** After cph#28 closes, re-run the falsification table with bilateral coverage; produce a substantive verdict for condition 3; report per-condition pass/fail with explicit n; separate measurement from interpretation; reconcile with the candidate support-path hypotheses surfaced in cph#27's field report.

## Phase R6 — AI classification

- **Goal:** Apply unsupervised or self-supervised structure-finding to per-cycle feature tables only after stable feature surfaces exist and survive confound checks.
- **Current evidence:** No clustering has been run. [`analysis/clustering-plan.md`](analysis/clustering-plan.md) exists as a plan-only document.
- **Gate:** A stable per-cycle feature table from R3 / R4 is available; unsupervised structure (clusters, embeddings, manifold organization) survives confound checks against trial crop, marker artifact, camera setup, subject morphology, and condition labels alone; clustering output is reported as candidate structure, not as confirmation of the seven gait families or the Coherence Path Hypothesis.
- **Status:** Not started.
- **Coherence risk:** The largest coherence risk in the project. Clustering output is the most likely surface to be read as hypothesis confirmation, since AI labels are easy to mistake for measurement. *Coherence laundering* — treating a clean clustering output (or a self-consistent repo) as substantive evidence for the hypothesis — is the failure mode to avoid. Adjacent risks: the seven gait families being reintroduced as proven categories by automated labels; the project's identity drifting from "test the hypothesis" toward "build a typology"; the safety boundary in [`README.md`](README.md) eroded by labels that read as diagnoses.
- **Next action:** Hold. Do not run clustering against existing or future data until R4 closes GO.
- **Owning files:** [`analysis/clustering-plan.md`](analysis/clustering-plan.md), future analysis documents.
